# SpeakSpace Local 本地大语言模型 / 小语言模型评估报告

## 摘要

本轮测试的 5 个模型都能在本地 Ollama 上成功启动，并完成英文、中文、印地语、混合 JSON 抽取和忠实问答任务。测试设备是 Mac mini，芯片为 Apple M4，运行内存为 16GB。所有模型在 `ollama ps` 中都显示为 `100% GPU` 调度。

综合速度、加载占用和人工复核质量，`Qwen2.5-3B-Instruct` 最适合作为 V1 默认候选。`Ministral-3-3B-Instruct` 的多语言任务质量接近或局部更好，但模型文件更大，加载后的常驻内存（RSS）也更高。`Qwen2.5-1.5B-Instruct` 速度最快、占用最低，但中文和印地语任务出现复述提示、占位文本、截断和事实错误，不建议作为默认模型。

> 证据：
> - 来源：`llm-evaluation/results/20260610-190012/summary.csv`、`detailed_results.csv`、`raw_outputs.md`
> - 方法：5 个模型各跑 5 个固定任务；通过 Ollama 本地接口非流式调用；人工复核原始输出
> - 置信度：中等。该测试是单设备、单轮小样本测试，适合做桌面端首轮筛选，不等同于最终生产基准。

| 测试设备 | Mac mini `Mac16,10` |

测试任务贴合 SpeakSpace Local 的语音转写后处理场景：

- 英文会议转写摘要、决策、行动项、风险提取
- 中文会议转写摘要、决策、行动项、风险提取
- 印地语会议转写摘要、决策、行动项、风险提取
- 中英印混合文本 JSON 结构化抽取
- 忠实问答，要求缺失信息回答“未提及”，原始提示词中使用的是 `not mentioned`

| Qwen2.5-1.5B-Instruct | `qwen2.5:1.5b-instruct` | 986 MB | 1.2 GB | 100% GPU | 1191 MB | 1433 ms | 4246 ms | 62.06 tok/s |

说明：

- `加载后大小` 来自 `ollama ps`。`预热后常驻内存` 是 Ollama 相关进程加载模型后的 RSS 快照，不是严格峰值内存。
- 5 个模型都能在 16GB 设备上跑起来，没有启动失败或本地接口调用失败。
- `Qwen2.5-1.5B-Instruct` 的速度优势很明显，但输出质量问题也最明显，不能只按输出词元速度判断。

## 任务质量

| 模型 | 英文任务 | 中文任务 | 印地语任务 | JSON 抽取 | 忠实问答 |
|---|---|---|---|---|---|
| Qwen2.5-3B | 好 | 好 | 可用，但小节不完整 | JSON 有效，项目名称略偏 | 正确 |
| Qwen2.5-1.5B | 可用但较浅 | 弱，包含占位文本 | 弱，复制输入且输出截断 | 去掉代码块标记后 JSON 有效 | 最后一题错误 |
| Phi-4-mini | 好 | 可用，但复述了转写原文 | 弱，复制/改写原文且截断 | JSON 有效，但错误改写 `Ministral` 名称 | 正确 |
| Ministral-3 3B | 好 | 好 | 好 | 去掉代码块标记后 JSON 有效 | 基本正确，但有一句自相矛盾 |
| Granite 4 Micro-H | 好 | 好 | 弱且不完整，错误展开大语言模型缩写 | JSON 有效 | 正确 |

人工复核重点：

- `Qwen2.5-1.5B-Instruct` 在缺失信息问答中，把“应该由哪个云厂商托管模型”回答成“桌面设备”（原始输出为 `desktop machine`），但正确回答应是“未提及”（原始提示词要求输出 `not mentioned`）。
- `Qwen2.5-1.5B-Instruct` 和 `Phi-4-mini-instruct` 的印地语输出都较弱，主要问题是复制提示词或转写原文，并在达到生成上限前没有完成要求的结构。
- `Phi-4-mini-instruct` 在 JSON 任务中把 `Ministral-3 3B` 改成了类似西里尔字母的字符串。
- `Granite-4.0-Micro-H` 的英文、中文和 JSON 输出可用，但印地语回答不完整，并把“大语言模型”缩写错误展开成“长短期记忆”（原始输出为 `Long Short-Term Memory`），这不符合本项目上下文。
- `Ministral-3-3B-Instruct` 在本轮测试中给出了最完整的印地语结构，但常驻内存和磁盘占用高于 `Qwen2.5-3B-Instruct`。

## 推荐结论

| 排名 | 模型 | 建议 |
|---:|---|---|
| 1 | `Qwen2.5-3B-Instruct` | 最适合作为 V1 桌面端默认候选。质量、速度、内存和模型大小最均衡。 |
| 2 | `Ministral-3-3B-Instruct` | 强备选模型，尤其适合继续观察印地语质量和结构化抽取质量。代价是磁盘占用和常驻内存更高，加载更慢。 |
| 3 | `Granite-4.0-Micro-H` | 英文、中文和 JSON 任务可用，但速度最慢且印地语较弱，不建议作为默认模型。 |
| 4 | `Phi-4-mini-instruct` | 能运行，英文/中文基本可用，但印地语质量和 JSON 名称改写问题使它对本项目有风险。 |
| 5 | `Qwen2.5-1.5B-Instruct` | 只建议作为低资源兜底模型。实际使用前需要更严格提示词、输出校验和更短的结构化定义。 |

建议项目下一步：

1. 将 `Qwen2.5-3B-Instruct` 作为主要桌面端大语言模型候选。
2. 保留 `Ministral-3-3B-Instruct` 作为质量挑战模型，重点继续测试印地语和结构化输出。
3. 只把 `Qwen2.5-1.5B-Instruct` 放进低资源配置档，不作为默认模型。
4. 在应用侧增加 JSON 校验和失败重试逻辑，因为部分模型会把 JSON 包在代码块标记中。
5. 用最终选定的 `whisper.cpp` 语音转写模型生成真实转写文本后，再跑第二轮大语言模型测试，因为真实转写错误可能改变后处理质量。

## 测试方法

本轮基准测试脚本是 `llm-evaluation/run_llm_benchmark.py`。

生成的实验材料：

- 汇总结果：`llm-evaluation/results/20260610-190012/summary.csv`
- 单任务指标：`llm-evaluation/results/20260610-190012/detailed_results.csv`
- 模型原始输出：`llm-evaluation/results/20260610-190012/raw_outputs.md`
- 环境快照：`llm-evaluation/results/20260610-190012/environment.json`

自动评分检查了响应是否存在、语言/文字系统是否匹配、结构是否大致符合要求、关键事实锚点是否覆盖，以及 JSON 是否可解析。最终推荐同时参考人工复核，因为自动评分没有捕捉到提示词复制、印地语输出截断、术语错误展开，以及 `Qwen2.5-1.5B-Instruct` 的忠实问答错误。

## 局限性

- 只测试了一台设备：Apple M4 / 16GB RAM。
- 每个模型每个任务只跑了一次，没有测延迟方差。
- 测试文本是受控的会议转写风格文本，不是真实 STT 输出，也没有包含识别错误。
- 常驻内存（RSS）和 `ollama ps` 是实用资源信号，不是严格的 Metal 统一内存峰值。
- 印地语质量只做了明显任务完成问题的人工复核，没有由母语审阅者做专业语言评分。
